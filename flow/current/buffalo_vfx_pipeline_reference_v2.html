Entity hierarchy

Show (Project)
  └─ Episode  code: 301, 302, 303
      └─ Scene  code: 001, 002, 003  ·  linked to Episode via sg_episode
          └─ Shot  code: 301_001_010, 301_001_020  ·  linked to Scene via sg_scene
              └─ Task  tied to Pipeline Step e.g. temp, comp
The pick_environment.py hook checks whether Shot.sg_scene is populated. If it is → episode_shot_step loads. If not → falls back to shot_step. Every shot must be linked to a Scene for the episodic config to activate.

Pipeline steps

Shot steps

dev→ model→ rig→ anim→ fx→ light→ temp→ comp→ mograph→ editorial→ deliverable

Asset steps

model→ rig→ lookdev→ fx
All shots begin as temp. Once the cut is locked, selected shots are finished in-house as comp or sent to an outside vendor. The review/ folder at the shot level holds dailies from both steps, keeping the version history unified per shot in ShotGrid.

Review workflow

Both tools write to shots/301/001/301_001_010/review/ and create a ShotGrid Version automatically.

Quick review

Proxy H.264 .mov rendered directly from the comp. No Write nodes executed. Fast — use for all dailies during temp work.

Submit for review

More control over slates and burnins. Also proxy only. Use for formal supervisor submissions.

Write nodes (full EXR renders → render/) must be executed manually. Full renders are expected only when a shot graduates to comp or is being delivered.

Rules for Claude across sessions

  1. Read PIPELINE_REFERENCE.md before writing any YAML or Python.
  2. Cross-platform paths always — every path needs linux_path, mac_path, windows_path.
  3. Templates before schema — define schema .yml first, then add template keys.
  4. Use shot_base for shared shot-level folders (plates, render, review, reference). Use shot_root for step-level folders (nuke/, maya/).
  5. No work/ or publish/ subfolders under steps — scripts sit directly in nuke/, maya/ etc.
  6. Step codes must exactly match ShotGrid Pipeline Steps. Flag mismatches — never silently change one side.
  7. Version pinning — all location: blocks must pin to a specific version. Update the versions table when bumping.
  8. Update the WIP list when items are resolved or new gaps are identified.
  9. No credentials or real paths in commits — use config/paths.local.yml (gitignored).
  10. Prefer includes over duplication — shared blocks go in env/includes/settings/.
